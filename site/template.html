Can a free AI model invent an optimization algorithm?

We asked open-weight language models to write search algorithms as Python code. Every program was tested on 24 standard benchmark problems, and the score went back to the model so it could try to do better. This page shows what the models came up with and how it compares with algorithms people designed.

The short answer

Score from 0 to 1 on problems the programs never saw while being written. Higher is better.

The idea

Finding the lowest point of a landscape you cannot see

Many real problems come down to the same task: choose numbers that make something as small as possible. That could be the cost of a design, the error of a model, or the length of a delivery route. Picture the possible choices as a hilly landscape, where height is the cost. You are blindfolded. You may test one spot at a time and are told its height, and you only get a limited number of tries. Where do you look next?

A search algorithm is a strategy for answering that question. People have invented many: some copy evolution, some copy flocks of birds, and some fit a statistical model of where the good spots are. Designing a good one takes experts years. We wanted to know whether a language model, given the task in plain text, could write one that holds up against the best human designs.

TechnicalThe problem, precisely

Each algorithm minimizes a black-box function f : ℝ5 → ℝ on the box [−5, 5]5 with a hard budget of 10,000 evaluations (2,000 × dimension, as in LLaMEA). The functions are the 24 noiseless BBOB functions from the COCO platform. Every algorithm, human or generated, implements the same signature, optimize(func, dim, bounds, budget).

The score is the area over the convergence curve (AOCC), as in LLaMEA: the best-so-far error after each evaluation, on a log scale clipped to [10−8, 102], averaged over the run and flipped so that 1 means the optimum was reached immediately and 0 means no progress. A crashed run scores 0.

The map below is a landscape seen from above, with darker bands lower down. Random guessing ignores what it has learned. An evolution strategy keeps the best spot so far, tries nearby, and widens or narrows its steps depending on how well that works. When it gets stuck, it restarts somewhere new.

On the smooth valley the evolution strategy finds the bottom fast. On the landscape with many traps it can get stuck in a dip and needs restarts. Real benchmarks mix both kinds, in five dimensions instead of two, which is why no single trick wins everywhere.

How it works

The language model is the inventor; our code is the judge

We rebuilt the LLaMEA method (van Stein and Bäck, IEEE TEVC 2025), which used paid GPT-4, with free open-weight models only. One run is 50 rounds of this loop.

Ask

A text prompt describes the task and the rules: Python only, numpy allowed, stay within the budget.

Write

The model replies with a complete search algorithm, a function called optimize, and gives it a name.

Check

Our audit scans the code before it runs and rejects anything that could cheat or escape. It runs in a separate process with a time limit.

Score

The program runs on all 24 benchmark problems, three versions each: 72 runs of 10,000 tries. The result is one score from 0 to 1.

Feed back

The model sees its score, its best program so far, its last ten attempts and any error message, then writes the next version.

Step 5 leads back to step 1. Fifty rounds per run, and the best program of the run is kept.

Two versions, to see whether the feedback matters

Arm A · with feedbackThe full loop above. A new program replaces the current best only if it scores at least as high.
Arm B · no feedback (control)Steps 1 to 4 only. The model gets the same plain prompt every time and never sees a score. We keep whichever program scored best.

Fair test

      
Making sure the AI could not cheat

      
A program that writes programs will find loopholes if they exist. We closed the ones we could think of, and tested that they stay closed.

    

    

    

      
Are these algorithms new?

      
Mostly they are new combinations of known parts. The names say as much: hybrids of differential evolution, CMA-ES, simplex search and particle swarms, or restart variants of CMA-ES. That matches published concerns about novelty claims in this field. The result we can stand behind is narrower: free models, with no human help, wrote programs that perform at the level of a widely used expert design.
